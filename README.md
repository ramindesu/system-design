# سیستم دیزاین؛ از مفهوم تا پیاده‌سازی با Python و Django

**۱۶ فصل فارسی · مثال عملی · آزمایشگاه مستقل · تمرین و پاسخ · مطالعهٔ آفلاین**

این مجموعه برای کسی ساخته شده که نام مفاهیمی مثل Cache، Load Balancer و Replication را شنیده و می‌خواهد بفهمد چطور کار می‌کنند، چه زمانی مفیدند و در کد چه شکلی دارند. مسیر فصل‌ها بر اساس کتاب **System Design Interview: An Insider’s Guide** نوشتهٔ **Alex Xu**، ویرایش دوم، تنظیم شده است.

توضیحات فارسی، مثال‌های Python/Django و تمرین‌ها برای این مجموعه تدوین شده‌اند؛ این مخزن ترجمهٔ کامل کتاب یا کد رسمی نویسنده نیست.

> هدف مطالعه: بتوانی مسیر یک درخواست را توضیح بدهی، دلیل انتخاب هر جزء را بفهمی، مثال را اجرا کنی و اثر یک تغییر را پیش‌بینی کنی.

## شروع سریع

۱. مخزن را Clone کن یا در GitHub گزینهٔ **Code → Download ZIP** را بزن و فایل را استخراج کن.

۲. فایل [index.html](index.html) را **از پوشهٔ دانلودشده در مرورگر** باز کن. این فایل فهرست فصل‌هاست؛ باز کردن HTML در GitHub معمولاً متن کد آن را نشان می‌دهد. برای خواندن جزوه‌ها به اجرای Django یا نصب کتابخانه نیاز نداری.

۳. از فصل اول شروع کن. برای مطالعهٔ مستقیم داخل GitHub، لینک نسخهٔ Markdown هر فصل در جدول پایین موجود است.

فونت **وزیر** داخل HTML تعبیه شده و متن‌ها راست‌به‌چپ‌اند؛ مطالعهٔ جزوه‌ها به اینترنت یا دانلود فونت نیاز ندارد. فایل مستقل فونت و متن مجوز آن هم در [assets/fonts](assets/fonts) قرار دارند و همراه مخزن قابل دریافت‌اند. نصب اولیهٔ وابستگی‌های Lab به اینترنت نیاز دارد.

## روش پیشنهادی مطالعه

برای هر فصل یک یا چند جلسهٔ حدود **۴۵ تا ۶۰ دقیقه‌ای** در نظر بگیر. فصل‌های سنگین‌تر مثل Key-Value Store، Chat، Video و File Sync ممکن است چند جلسه زمان بخواهند.

۱. **مسئله را بفهم.** قبل از کد بنویس چه چیزی می‌سازیم، چه محدودیتی داریم و موفقیت را چطور می‌سنجیم. مثلاً: «تعداد خواندن‌ها زیاد است؛ نتیجهٔ قدیمی چه زمانی قابل قبول است؟»

۲. **مسیر درخواست را رسم کن.** از کاربر تا سرویس و دیتابیس یک نمودار ساده روی کاغذ بکش. مشخص کن داده کجا خوانده یا نوشته می‌شود و با خرابی هر بخش چه اتفاقی می‌افتد.

۳. **کد را با سؤال بخوان.** برای هر Query یا تابع بپرس: چرا اینجا اجرا می‌شود؟ چرا این دیتابیس؟ چرا Transaction؟ چرا این کلید Cache؟ قبل از اجرا، خروجی را حدس بزن.

۴. **Lab را اجرا و یک چیز را تغییر بده.** ابتدا مثال آماده را اجرا کن، سپس فقط یک ورودی یا تنظیم را عوض کن. نتیجهٔ واقعی را با پیش‌بینی خودت مقایسه کن.

۵. **تمرین را قبل از پاسخ حل کن.** حتی اگر جواب کامل را نمی‌دانی، فرض‌ها و راه‌حل خودت را بنویس. بعد پاسخ جزوه را بخوان و دلیل تفاوت را پیدا کن.

۶. **از حافظه توضیح بده.** در پایان، چند خط دربارهٔ مسئله، تصمیم اصلی، محدودیت و یک حالت خرابی بنویس. جلسهٔ بعد، بدون نگاه به پاسخ، یک تمرین را دوباره انجام بده.

معیار رفتن به فصل بعد این است که بتوانی **دلیل تصمیم‌های اصلی** را با زبان خودت توضیح بدهی و یک تغییر کوچک در مثال انجام بدهی. تمام شدن صفحات یا سبز شدن تست‌ها به‌تنهایی کافی نیست.

### اولین تمرین: Primary و Replica

در فصل اول، بخش Replication را بخوان و Lab را طبق راهنمای آن آماده کن. سپس:

- قیمت یک کتاب را از Primary و Replica بخوان.
- قیمت را با سرویس `update_price` تغییر بده.
- قبل از خواندن دوباره حدس بزن هر دیتابیس چه مقداری نشان می‌دهد.
- بعد از اجرای `snapshot_replica` دوباره مقایسه کن.
- توضیح بده چرا صفحهٔ تأیید تغییر قیمت ممکن است به خواندن از Primary نیاز داشته باشد.

در این آزمایش، Replica یک SQLite مستقل است که **دستی Snapshot می‌شود**. این کار رفتار دادهٔ قدیمی را نشان می‌دهد و Replication واقعی PostgreSQL را راه‌اندازی نمی‌کند. بعد از درک این قسمت، سراغ Cache و Transaction برو.

## اجرای آزمایشگاه‌ها

پیش‌نیاز پیشنهادی **Python 3.12** است. وابستگی پایهٔ پروژه‌ها **Django 5.2.18** است و در `requirements.txt` هر فصل مشخص شده است. برای مسیر پایه، نصب Docker، PostgreSQL، Redis یا اتصال به سرویس ابری لازم نیست.

### فصل‌های ۲ تا ۱۶

مثال زیر برای فصل دوم است. فرمان‌ها را از ریشهٔ همین مخزن اجرا کن؛ برای فصل‌های بعد مسیر فصل را عوض کن:

```bash
cd "فصل ۰۲/lab"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py test
python demo_script.py
```

در Windows PowerShell برای ساخت محیط مجازی می‌توانی از `py -3.12 -m venv .venv` استفاده کنی. به‌جای فعال‌سازی، فرمان‌های بعدی را با Python داخل محیط اجرا کن:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe demo_script.py
```

`demo_script.py` دادهٔ تمرینی را ایجاد یا بازنشانی می‌کند؛ آن را در همین Lab اجرا کن. برای آزمایش دستی، `python manage.py shell` را باز کن. مسیر اصلی یادگیری بیشتر Labها **Shell، سرویس و تست** است؛ همهٔ فصل‌ها صفحهٔ وب یا API عمومی ندارند.

برای جابه‌جایی بین فصل‌ها، محیط فعلی را با `deactivate` ببند، به پوشهٔ Lab بعدی برو و محیط همان فصل را بساز یا فعال کن. اگر از مسیر مستقیم Python محیط مجازی استفاده می‌کنی، نیازی به فعال‌سازی یا `deactivate` نیست.

### فصل اول: دو دیتابیس و Replica آموزشی

فصل اول راه‌اندازی متفاوتی دارد. از ریشهٔ مخزن:

```bash
cd "فصل ۰۱/lab"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate --database=default
python manage.py migrate --database=replica
python manage.py seed_demo
python manage.py snapshot_replica
python manage.py test
REPLICA_ENABLED=1 python manage.py shell
```

مراحل کامل، مثال تغییر قیمت و اجرای وب در [راهنمای فصل اول](فصل%20۰۱/lab/README.md) آمده‌اند. در PowerShell برای فعال‌کردن Replica ابتدا `$env:REPLICA_ENABLED="1"` را تنظیم کن و سپس Shell را با Python محیط مجازی اجرا کن.

نیازهای اختیاری مثل Channels و S3 جدا از مسیر پایه‌اند؛ توضیحات و وابستگی‌های آن‌ها در فصل مربوط قرار دارند.

## چه چیزهایی در Git حفظ می‌شوند؟

فایل [`.gitignore`](.gitignore) فقط محیط‌های مجازی، کش و خروجی‌های موقت، اطلاعات محلی `.env`، فایل‌های موقت ویرایشگر و دیتابیس‌های اجرای این Labها را کنار می‌گذارد.

**جزوه‌های HTML و Markdown، همهٔ کدهای Lab، Migrationها، تست‌ها، فایل‌های requirements، مجوز فونت، گزارش‌های بررسی و بسته‌های ZIP قابل ثبت در مخزن هستند.** پوشهٔ `lab` و تنظیمات Python نادیده گرفته نمی‌شوند. نمونه‌های `.env.example`، `.env.sample` و `.env.template` هم قابل ثبت‌اند.

نادیده گرفتن دیتابیس به معنای حذف آن از سیستم تو نیست؛ داده‌های فعلی روی دیسک باقی می‌مانند. روی یک Clone تازه، `migrate` دیتابیس را می‌سازد و فرمان‌های Seed یا Demo دادهٔ آموزشی لازم را فراهم می‌کنند. تغییراتی که فقط در دیتابیس محلی انجام بدهی با Git منتقل نمی‌شوند؛ برای نگه‌داشتن یک تمرین قابل تکرار، آن را به کد یا Fixture تبدیل کن.

## بررسی‌ها و محدودهٔ مثال‌ها

در بررسی ثبت‌شدهٔ مجموعه، **۵۹ تست رفتاری Labها موفق شده‌اند**. نتیجهٔ هر فصل در [verification.json](verification.json) و فهرست فصل‌ها در [manifest.json](manifest.json) موجود است. فصل‌های ۲ تا ۱۶ با دیتابیس‌های SQLite تازه و اجرای Demo نیز بررسی شده‌اند. این گزارش مربوط به آماده‌سازی مجموعه است؛ CI خودکار روی GitHub در این مخزن تنظیم نشده است.

- آزمایشگاه‌ها برای یادگیری و اجرای محلی‌اند؛ تنظیمات آن‌ها برای استقرار عمومی آماده نیستند.
- بررسی با SQLite، رفتار واقعی Row Lock و همزمانی PostgreSQL، Failover، ظرفیت Cluster یا کارایی Production را ثابت نمی‌کند.
- مثال‌های اعلان و Storage شبیه‌ساز محلی دارند؛ Demoها ایمیل، پرداخت یا درخواست شبکهٔ خارجی انجام نمی‌دهند.
- نمونهٔ Channels در فصل Chat و Connector مربوط به S3 در فصل Video اختیاری‌اند؛ اتصال واقعی آن‌ها در بررسی پایه اجرا نشده است. نمونهٔ ویدئو Transcoding واقعی ندارد.
- اعداد و نمونه‌های تاریخی کتاب را باید با فرض‌های مسئلهٔ خودت بازبینی کنی.

اعلان مجوز فونت وزیر در HTMLها و [FONT-LICENSE.txt](فصل%20۰۱/FONT-LICENSE.txt) حفظ شده است. حقوق کتاب مرجع متعلق به نویسنده و ناشر آن است.
